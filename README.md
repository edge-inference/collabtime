# Warehouse Distributed Shared Memory System

A comprehensive distributed shared memory (DSM) system for warehouse robotics, combining Mesa agent-based modeling with Lingua Franca deterministic coordination.

## Overview

This system implements a distributed shared memory architecture for coordinating warehouse robots. It uses Mesa for agent-based simulation, NetworkX for graph operations, and Lingua Franca for deterministic timing coordination. The DSM system enables robots to share state information efficiently while maintaining consistency and handling network partitions.

## Features

### Core DSM Capabilities
- **Distributed Memory Management**: CRDT-based shared memory with conflict resolution
- **Halo Gossip Protocol**: Efficient state propagation between memory owners
- **Age of Information (AoI) Constraints**: Freshness guarantees for shared data
- **Partition Tolerance**: Graceful handling of network partitions and failures
- **Task Coordination**: Distributed task claiming and execution

### Simulation Framework
- **Mesa Integration**: Agent-based modeling with robot state machines
- **Warehouse Topology**: Configurable storage, sortation, and navigation areas
- **Task Management**: Dynamic task generation with pickup, delivery, and sorting
- **Performance Metrics**: Comprehensive data collection and analysis

### Lingua Franca Coordination
- **Deterministic Timing**: Real-time coordination with logical time progression
- **Federated Architecture**: Distributed execution across multiple nodes
- **Reactor Model**: Event-driven coordination with memory owners and agents

## Quick Start

### Running Basic Simulation

```python
from world.model import WarehouseDSMModel
from world.graph import WarehouseGraph
from dsm.api import DSM

# Create warehouse graph
graph = WarehouseGraph(width=10, height=10)
graph.add_storage_location((2, 2))
graph.add_sortation_location((8, 8))

# Initialize DSM
dsm = DSM(memory_owners=2, partition_strategy="spatial", halo_radius=2)

# Create and run model
model = WarehouseDSMModel(
    n_agents=4,
    warehouse_graph=graph,
    dsm=dsm,
    task_arrival_rate=0.2
)

# Run simulation
for _ in range(100):
    model.step()

print(f"Tasks completed: {len(model.completed_tasks)}")
```

## Architecture

### Distributed Shared Memory

The DSM system implements a distributed memory architecture with the following components:

- **Memory Owners**: Manage partitions of the global state space
- **Halo Gossip**: Propagate state updates between adjacent partitions
- **CRDT Merging**: Resolve conflicts in distributed updates
- **AoI Tracking**: Ensure data freshness constraints

### Agent State Machine

Robot agents follow a state machine pattern:

1. **Idle**: Waiting for tasks or coordination
2. **Bootstrap**: Initial DSM synchronization
3. **Coverage**: Area coverage when no tasks available
4. **SelectTask**: Choose and claim available tasks
5. **Execute**: Perform task actions (pickup, delivery, sort)
6. **Complete**: Finish task and update DSM

### Coordination Patterns

- **Task Claiming**: Distributed coordination to avoid conflicts
- **Path Planning**: Shared obstacle and congestion information
- **Load Balancing**: Dynamic task redistribution based on agent capacity

## Configuration

### Experiment Configuration

Experiments are defined in YAML files with the following structure:

```yaml
experiment_name:
  warehouse:
    size: [width, height]
    storage_regions: [{center: [x, y], radius: r}]
    sortation_regions: [{center: [x, y], radius: r}]
  agents:
    count: N
    initial_positions: [[x1, y1], [x2, y2], ...]
  dsm:
    partition_strategy: "spatial" | "spectral"
    memory_owners: N
    halo_radius: R
    aoi_threshold: T_ms
  tasks:
    arrival_rate: rate_per_second
    types: ["pickup", "delivery", "sort"]
    priorities: [weight1, weight2, weight3]
  simulation:
    duration: seconds
    step_interval: milliseconds
```

### DSM Parameters

- **Partition Strategy**: "spatial" (grid-based) or "spectral" (graph cut)
- **Halo Radius**: Overlap distance between partitions
- **AoI Threshold**: Maximum allowed data age in milliseconds
- **Gossip Interval**: Frequency of state synchronization

## Performance

### Metrics Collected

- **Task Performance**: Completion rates, times, success ratios
- **Agent Efficiency**: Utilization, distance traveled, idle time
- **DSM Operations**: Read/write counts, gossip overhead, AoI violations
- **System Resources**: CPU, memory, network usage

### Scalability

The system has been tested with:
- Up to 25x20 warehouse grids
- 12+ concurrent agents
- High task arrival rates (1.2 tasks/second)
- Network latency simulation (10-100ms delays)
